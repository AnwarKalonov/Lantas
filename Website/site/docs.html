getting started

Installation

Lantas is a macOS app, built from source. You need macOS 13 or newer, Chrome 116 or newer, Node 20 and a Rust toolchain once. The installer builds the app, signs it for your Mac, and puts it in Applications.

$git clone https://github.com/AnwarKalonov/Lantas.git

Then double-click the installer, or run it from the terminal:

$open "Build Lantas.app.command"

It takes about two minutes. When it finishes you have Lantas.app with the Chrome extension inside it, at Contents/Resources/chrome-extension.

The build is ad-hoc signed, not notarized. On first launch macOS may ask you to confirm. If it refuses, right-click the app, choose Open, then Open again.

Start it

$open -a Lantas

There is also Lantas.command in the repo, for the web build while you are working on the UI. It is not the app.

getting started

First run

Lantas opens on the chat. Three things to do once:

  1. Open Settings → Providers, pick Anthropic, OpenAI, Gemini, DeepSeek or an OpenAI-compatible endpoint, and paste a key.
  2. Pick the model the agent should use. The model list is fetched from the provider when a key is present.
  3. Open Browser, then Chrome extension, and load the extension folder Chrome is told about.

Keys live in the app's own storage on your Mac. They are not synced, not proxied through a server, and never committed anywhere.

Without a provider the app still opens and the browser still works. The agent will say it needs a key rather than answer.

getting started

Quickstart

Four steps, and the first task takes about a minute.

  1. Install the app and open it. Build Lantas.app.command does both.
  2. Load the extension once: chrome://extensions → Developer mode → Load unpacked → the folder the app shows you.
  3. Open the page you care about in Chrome, then click the Lantas icon. The side panel opens on the right.
  4. Ask. “Summarise this page”, “find the invoice and download it”, “click Place order”.

The app has to be open: the panel talks to it over a loopback socket on 127.0.0.1:47654. If the app is closed the panel says so instead of pretending.

getting started

The Lantas window

Three modes, one window, and a side panel that can sit in any of them.

chat
A thread with the agent. Slash commands, attachments, screen capture, the usual.
code
A workspace folder, files in the tree, and the diff the agent wants to apply.
browser
Lantas' own webview, or your real Chrome through the extension. A home page with bookmarks, history and a star beside the address bar.
the rail
Ask about the page you are on without leaving it. The switch at the bottom is whether the agent may act.

Colour has one job in the browser: the accent marks what is live or selected, red marks a failure, and everything else is grey.

the browser

Two engines

The browser tab has a switch with two positions.

lantas
A native webview inside the app. Pages render in Lantas, links stay in Lantas, and the agent reads them through the app.
chrome
Your real Chrome. Lantas sends commands to the extension and the extension acts in the tab you have open, with your logins and your extensions.

Use the Lantas engine for reading and research; use Chrome for anything that needs you signed in. The engine is remembered between launches, and the browser always opens on its home page.

Some sites refuse to load in a webview at all — Notion, Google Docs, most banks. That is what the Chrome engine is for.

the browser

The Chrome extension

A side panel, not a popup. Click the Lantas icon in the toolbar and the panel opens on the right of the tab you are reading.

Load it once. The app shows the folder, or use this path:

$/Applications/Lantas.app/Contents/Resources/chrome-extension

What the panel shows

status
Connected or not, and the app it is talking to
the page
Title, address and how many controls the agent can see
the thread
Your questions, its answers, and a note for every action it ran
let lantas act
The kill switch. Off means read-only, immediately

How it talks to the app

The extension opens a WebSocket to ws://127.0.0.1:47654 and says hello. The app only accepts chrome-extension:// origins, so a website cannot pretend to be the extension. Commands go one way, results and answers come back with the same id.

Reloading the extension gives it a new id and breaks the connection until Chrome reconnects. Keep the folder in one place.

the browser

Reading the page

The content script returns four things, and nothing else:

title · url
What the tab says it is, with query strings and fragments intact
text
Visible text, cleaned of scripts and styles, capped so one long page cannot eat the context
controls
Buttons, links, inputs, selects and textareas: role, accessible name, value, whether visible and enabled
elements
A short numbered list of the labelled controls, so the model can name one instead of guessing coordinates

Nothing is captured as an image. There is no OCR, no screenshot, and no cursor tracking. A page the extension cannot script — chrome://, the Web Store, PDF viewers — is reported as unreadable rather than half-read.

Iframes on another origin, closed shadow roots and canvas-only apps are read as text at best. Lantas says which part it could not see.

the browser

Acting on the page

Seven actions, one at a time:

ActionWhat it needs
clickThe label of the control, or a CSS selector as a fallback
typeThe text, and a field by label or selector; optionally submit
enterNothing: Enter goes to the focused field
scrollPixels up or down
openA URL, in the current tab or a new one
back · forwardNothing
reloadNothing

How a click finds its target

By label first. The extension scores the control's accessible name against what the model asked for; a button that moved is still a button. A CSS selector is the fallback, and coordinates are never used. If two controls match equally well, the agent asks instead of picking one.

What it will not do

It does not press anything destructive without the word in your request, does not type into password or payment fields without an explicit ask, and does not click a disabled control. When the switch is off, every action is refused in the extension before it reaches the page.

After every action

The page is read again. If the confirmation the step expected is not there, the action is reported as failed — with what the page actually said — rather than as done. The answer you read in the panel is the step that ran, not a description of it.

Providers and keys

Anthropic
Claude models, streaming, tool use
OpenAI
GPT models, streaming
Gemini
Gemini models through the Google endpoint
DeepSeek
Chat and reasoner models
OpenAI-compatible
Any base URL: a local server, a gateway, or your own proxy

The default model is yours to choose per session, and the agent switch in the browser rail uses the same provider. Nothing is sent to Lantas: requests go from your Mac to the provider you picked, with the key you pasted.

A local endpoint needs no key. Set the base URL to http://127.0.0.1:11434/v1 or whatever your server serves, and pick a model name it knows.

models

What a task costs

Two parts: the model, and the machine.

the model
Eleven browser tasks averaged $0.12 each on Sonnet 4.5, at about 1.8 minutes a task
the machine
0.06 s to read a page of 42 controls, 0.11 s to match locally

Cost tracks the page, not the app: a long article is more tokens than a login form, and a task that needs six steps pays for six model turns. The panel shows the model it is using, so you are never guessing which bill you are adding to.

Caveats

  • Eleven tasks is a sample, not a study. The tasks were written by us, and we knew what the right answer looked like.
  • Timing is wall clock, from the first prompt to the page saying the task was done. A tool that gives up is not counted as fast.
  • Cost is the provider's list price at the time of the run, not a discounted rate.
  • The three tools were run on different models because those are the models each is built around.

reference

Overhead

Where a two-step task spends its 2.3 seconds of machine time:

reading the page
0.06 s for 42 controls, through the extension
matching
0.11 s locally, no model
the model
2.1 s, waiting on the provider

The app is a native Tauri binary. Its idle cost is a window and a socket; there is no browser engine running until you open the browser tab, and no polling loop when the panel is closed. The bridge keeps one socket per Chrome profile.

reference

Security

the bridge
Loopback only, and it refuses any origin that is not chrome-extension://
page data
Sent to your provider with the question you asked, and nowhere else
keys
Stored in the app's own storage on your Mac, never in the repo
telemetry
None. There is no analytics endpoint to turn off
the switch
“Let Lantas act” off means the extension refuses every action

The extension asks for tabs, scripting, storage and sidePanel. It reads a page only when a question or an action needs it; it does not run in the background on every site you visit.

Troubleshooting

The app will not open

macOS quarantined the ad-hoc build. Right-click Lantas.app, choose Open, then Open again. If it still refuses, run xattr -dr com.apple.quarantine /Applications/Lantas.app.

The panel says “Lantas is closed”

The app is not running, or the bridge port is taken. Open Lantas; if it is already open, quit it and start it again. The port is 127.0.0.1:47654.

Chrome will not load the extension

Chrome 116 or newer is required. In chrome://extensions, turn on Developer mode, choose Load unpacked, and pick the chrome-extension folder inside the app bundle. Loading it from a moved folder gives a new id.

It cannot read a page

chrome:// pages, the Chrome Web Store, the PDF viewer and other extensions' pages cannot be scripted. Switch to a normal website tab.

It clicked the wrong thing

Say which control you meant by its visible words. Matching is by label; if the page has two buttons with the same name, Lantas asks rather than picking one. The side panel shows the label it matched.

A provider call fails

Check the key and the model name in Settings → Providers. A 401 is the key, a 404 is usually the model id, and a timeout is the network. The panel reports the provider's own message rather than a generic error.
