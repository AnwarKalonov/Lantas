Training observability

      
A dashboard plots what you logged. Pulse reads the computation.

      
Understanding training failures: the difference between observing a metric and understanding the computation that produced it.

    


    

      

        
A 380M-parameter model is 380,000,000 numbers, and any one of them can be the problem. A dashboard plots what you chose to log; a general-purpose assistant sees what you paste into it. Pulse instead attaches to the running process and tracks tensors, gradients, activations, weights, loss, metrics and scalar histories as they change, with no modifications to your training code.

        
For each variable Pulse keeps shape, dtype, device, statistics, NaN/Inf status and history. GPU data is touched only on request: /gputrack is opt-in.

All four on cuda:0, read a few times a second from a background thread. No NaN or Inf on any of them, and only 0-d and few-element values cross the device boundary.

      

    


    

      

        
Why “residual”

        

          Every prediction leaves something over, and the leftover is where bugs hide. From the Latin residuum, “that which remains.”
        


        
For a target yi and the model's prediction ŷi, the residual is the part the model did not explain.


        

          
            ei=yi−ŷi
          
          The residual: the part the model did not explain.
        


        

          Most of the time the residual is noise. Sometimes it is the whole story; the figure draws one, and its points can be clicked.
        

      


      
    


    

      
Failures that do not announce themselves


      

        

          
At 03:07 AM the loss was fine. Then it was not. NaN stands for “not a number”; it is the only value not equal to itself, and it spreads to everything it touches. By the time you wake up, the run has spent eight hours learning nothing.

          
Pulse raises NaN and Inf findings immediately. Every other check must hold for two consecutive evaluations first.


          

            x≠x⇔x=NaN
            The only value that is not equal to itself.

Root-cause analysis

        
Separating computation from conjecture

      

      
Instead of asking a model to estimate whether a gradient or update looks large, Pulse calculates it.

    


    

      

        
Pulse separates AI reasoning from exact numerical calculation. Deterministic checks compute quantities such as gradient and update ratios, scaling factors and normalization statistics directly, so the agent starts from measured facts rather than impressions.

        
When a check holds, Pulse raises a finding: a check id, a variable, a severity, its numbers and a confidence. Findings are deduplicated on the pair (check, variable), so a spike to 4.12 and a spike to 4.13 are one problem, not two. Detection runs whether or not auto-fix is on.

What the agent reads

      

        

          
The agent reads that evidence together with your source code, and the root cause it reports keeps facts apart from model guesses. Two further passes cover what single checks miss: a static ML lint for incompatible loss and metric combinations, backward() without an optimizer update, train/eval mode mistakes and suspicious learning rates; and a periodic audit of the whole run for a loss that decreases far slower than it should, or two metrics that disagree.

Agentic intervention

      
Acting on what it finds

      
Every change is a diff you can review, and one /undo away.

    


    

      

        
With auto-fix on, Pulse can pause training when detection finds a serious numerical or training problem, so the agent can investigate before more compute is wasted. The agent proposes the smallest change that explains the failure: a single-line edit first, a small adjacent change next, a larger edit only when necessary. It shows the diff and asks before applying.

        
In auto mode a separate approver model answers the y/N prompts for risky commands and for each proposed edit, and is told to deny when unsure. Set "approver": "off" to answer yourself.

      


      

        

          
01Detecta check holds twice

          
02Pauseonly when it is serious

          
03Proposesmallest edit first

          
04Decideyou, or the approver

          
05Verifyone /undo away

        

        
The auto-fix loop. The last three stages are why a fix is safe to try: you or the approver decide, and nothing is permanent.

Verification

        
Measured on injected faults

      

      
Each tool must find the cause and apply the fix.

    


    

      
We injected eleven ML faults into real training code and asked each tool to find the cause and apply the fix. Pulse ran on DeepSeek v4.1; Claude Code ran on Opus. Over the cases each tool fixed, Pulse took a mean of 1.3 minutes at $0.19 per task, against 3.9 minutes and $0.39 for Claude Code. Pulse fixed all eleven; Claude Code fixed nine, missing one fault and finding another without applying it.

What Pulse is not

      
Not a replacement: general agents are broader, and dashboards are good for browsing history. Pulse is narrower on purpose: the live run.

    


    
General agents and passive dashboards each solve part of the problem. Pulse is built around the part they leave to you: watching the run, checking the numbers, and acting on what it finds.

Installation

        
Install and start

      

      
Needs Python 3.9+ and a supported backend: PyTorch, TensorFlow, JAX, CuPy or NumPy.

    


    

      

        
Pulse adds about 20 MB of overhead. With no API key, sign in with OpenRouter from inside Pulse and use free models. Or bring your own key: Anthropic, OpenAI, Gemini, DeepSeek, Mistral or OpenRouter. A pasted key is never written to disk.

        
Download the build that matches your system, or install from PyPI, then start the app; setup takes it from there.
